# 更新發布與驗收

## 發布契約

- Windows x64、免安裝資料夾、Velopack 1.2.161；更新來源固定為 `00vchannel/TseroShortClipBoard` 的正式 GitHub Releases。
- 主程式與打包版本必須一致。`Build-UpdateRelease.ps1` 預設讀取 `ClipboardApp/ClipboardApp.csproj` 的 `Version`；正式打包若指定不同版本會停止，只有隔離測試包可以覆寫版本。禁止覆寫同一已發布版本附件。
- 只使用 `win-x64` 通道及完整更新套件。發布附件包含 `ZeroZeroClipboard-win-x64-Portable.zip`、該版本 `*-full.nupkg`、`releases.win-x64.json`。工具額外產生的 Setup 並不是本計畫的發行入口。
- 發布前先在 GitHub 草稿 Release 準備齊全附件，核對 SHA256 與版本後才公開。公開發布、推送與本機正式切換各需獨立授權。
- 本機下載的執行檔尚未簽章；檔案雜湊只能檢查完整性，不能替代發行者簽章。

## 本機打包

先將固定版本工具安裝在專案內：

```powershell
dotnet tool install vpk --version 1.2.161 --tool-path .build-tools --add-source https://api.nuget.org/v3/index.json
./tools/Build-UpdateRelease.ps1
```

腳本只建立本機輸出，不會上傳、不替換正式程式。輸出資料夾已存在時會停止，避免混入前次版本的檔案。不要直接使用舊有單檔發行方法；發布資料夾必須包含 `ClipboardUpdateHandoff.exe`。

## 隔離驗收

`UpdateTestBuild` 會加入專用測試入口，資料只寫入具有隔離標記的新資料夾，不註冊快捷鍵、系統剪貼簿監聽或開機啟動。這些套件一律不可發布。

```powershell
./tools/Build-UpdateRelease.ps1 -Version 2.1.0 -OutputDirectory artifacts/qa/old -UpdateTestBuild
./tools/Build-UpdateRelease.ps1 -Version 2.1.1 -OutputDirectory artifacts/qa/new -UpdateTestBuild
./tools/Test-UpdatePackages.ps1 -PreviousRelease artifacts/qa/old/releases -NextRelease artifacts/qa/new/releases -TestDirectory artifacts/qa/run
```

驗收沿用實際更新服務、保存流程、交接程序與 Velopack 替換，只將 GitHub 來源換為本機測試套件。重開後必須得到 `acceptance.json`，確認版本、搜尋、草稿與正式文字；同時檢查上一版和 SQLite 備份存在。不可把模擬下載測試當作實際網路下載驗證。

`ClipboardApp.Smoke` 另外覆蓋：無新版／未知狀態、正式版篩選、取消、重複下載、失敗重試、鍵盤 Enter、主題與文字縮放。`ClipboardCore.Tests` 覆蓋一致性備份與各表筆數／內容雜湊。

## 交接與恢復

正常下載可取消。完成後等輸入及對話框結束，暫停寫入，保存草稿並核對備份與完整上一版。更新交接程序位於資料目錄，等待原程序退出，要求正常退出標記及成功退出碼才呼叫更新工具。它不會強制終止原程式。

交接持有鎖時，新啟動的本程式會立即離開，避免讀写正被替換的資料夾。Velopack 的啟動自動安裝功能已關閉。下一次正常啟動會先檢查交接紀錄及資料，再恢復剪貼簿監聽。

`updates/<作業編號>/` 保留 `before-update.sqlite`、`previous/`、`job.json`、`result.json` 和復原說明；交接錯誤另記 `handoff-error.txt`，安裝工具記 `installer.log`。這些檔案包含本機路徑與搜尋狀態，不得提交或上傳。不同作業不共用資料夾，也不自動删除復原資料。

資料庫格式目前固定為 1。未來若需變更，必須先設計相容性與遷移核對流程，不能直接沿用本版逐表內容相同的判斷。
